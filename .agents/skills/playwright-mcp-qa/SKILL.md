# Проверка веб-реализации через Playwright MCP

После реализации задачи, влияющей на браузерный интерфейс или пользовательское веб-поведение, обязательно выполни проверку через Playwright MCP до сообщения о завершении.

## Инструмент

Для любых действий с браузером в этом проекте используй Playwright MCP (`mcp__playwright__*`). Не заменяй его HTTP-запросами, terminal-browser или ручной проверкой кода.

## Порядок проверки

1. Определи адрес и маршрут из README, конфигурации или задачи. Не запускай и не останавливай сервисы без необходимости; если они недоступны, сообщи, что именно мешает проверке.
2. Открой затронутый маршрут через Playwright MCP и зафиксируй исходное состояние accessibility snapshot.
3. Пройди основной пользовательский сценарий изменённой возможности. Для форм проверь успешный сценарий и релевантную валидацию или ошибку, если она изменилась.
4. Проверь результат через snapshot: ожидаемые тексты, состояние, навигация и доступные интерактивные элементы должны соответствовать задаче.
5. Проверь вёрстку скриншотом Playwright MCP на типичном desktop viewport. Убедись, что ключевой контент виден, не перекрыт и элементы управления расположены и читаемы. При затронутой адаптивности повтори на соответствующем мобильном viewport.
6. Просмотри ошибки консоли. Не относи к реализации известные, воспроизводимые до изменения ошибки, но укажи их в результате проверки.

Используй refs из актуального snapshot для взаимодействия, а не устаревшие селекторы. Не применяй `browser_run_code_unsafe`, если стандартных инструментов Playwright MCP достаточно.

## Итог

В финальном сообщении кратко укажи проверенный маршрут, сценарий и результат визуальной проверки. Если обязательную проверку выполнить не удалось, не называй задачу полностью завершённой: укажи причину и действия, нужные для запуска проверки.
